# Document

Follow the references below only as needed; never upfront.

- ./document.md - when naming things: a document holds tabs; diagram, event-storming board, markdown and file are tab kinds; whiteboarding is an editor mode
- ./document-branches.md - when a document has named live copies beside main: starting, naming, viewing, comparing, merging (pages by character, diagrams by element), unmerged changes, discarding and restoring
- ./file-tab.md - when any file (an image, a PDF, a script) lives in LiveDoc as a document: the file tab kind, its bytes, previews, whole-file changes, limits
- ./document-structure.md - when working on Document structure: Documents contain tabs; elements can link across tabs
- ./document-storage.md - when touching where a document's content is stored or read: one SQLite-backed Durable Object per document (`DocumentRoom`) holds its content; D1 keeps the listing and the cross-document indexes its outbox feeds
- ./document-storage-move.md - when moving existing documents' content from D1 into their rooms: the one-shot move, its verification, rollback and the later drop
- ./per-tab-storage.md - when working on Per-tab storage: Split tabs into their own D1 rows so autosave scope shrinks
- ./tab-document-many-to-many.md - when working on Tab ↔ document many-to-many: Link table so a tab can live in multiple documents
- ./tab-folders.md - when working on Tab folders: Group a document's tabs into one-level named folders that fan out from one chip
- ./document-snapshots.md - when working on Document SVG snapshots: One R2-cached SVG per document, rendered on-read-if-stale: Explorer row thumbnails (owner-authed) + the live image share embed ([Live image share link](../013-workspace/live-image-share.md), share-code-scoped). Gated on the optional R2 binding
- ./layers.md - when working on Layers: Photoshop-style per-tab layers: Tab.layers bands + element layerId, active layer receives new elements, visibility/lock/reorder, band-scoped z-order, a Layers panel (a popover over its bottom-right cluster button), hidden layers excluded from exports behind an export-dialog toggle
- ./offline-mode.md - when working on Offline Mode: Per-document mode (the This Browser save location: the default for a guest, opt-in for a signed-in person) that saves only to the browser (IndexedDB), never to the API, and opens instantly without waiting on the server — images embedded locally, server-only features (teams / AI / live) hidden and Share explaining and offering Sync Document, which converts the open document in place with no reload, an "Offline" badge in the header + Explorer. Convertible both ways: "Save to your account" (Offline → Cloud) and "Take offline" (Cloud → Offline, deleting the server copy, with confirmation). Folded into the marketing privacy area + a help article
- ./name-length.md - when working on Tab and document name length: Tab + document names capped at 60 chars with whitespace collapsed and word-boundary ellipsis truncation; enforced by the api worker on every stored name (editor, API tokens, MCP, copies) and at the editor's mutation points (auto-naming, renames, /new wizard) with `maxLength` on the inputs as a visible second line of defence
- ./save-locations.md - when working on Save Locations: The New Document wizard's "Save Offline, This Browser Only" toggle becomes a **Save location** row of tiles (LiveDoc, the default, and This Browser; the default depends on who is creating: This Browser for a guest), built on the same `PlacementCard` as the Save In row so the two read as one family. A toggle could only ever answer yes or no; a catalogue (`lib/save-locations.ts`, `NewDocumentSettings.saveLocation`) is what a third store (GitHub, say) can be added to as one entry, one glyph, and one create branch. Google Drive is a mirror of cloud documents, never a location. Only shipped locations are shown, no "coming soon" tiles
- ./stroke-points.md - when reading or writing a freehand stroke's points: the `packedPoints` binary block (16-bit x, y and optional 8-bit pressure per point, base64), its precision guarantee, lazy memoised decoding, validation rejections and the migration of stored `{ nx, ny }` points
- ./blueprints/README.md - when implementing or changing a document-model feature from its blueprint
