# Document blueprint defaults

One row per default applied where a spec is silent or qualitative.

| #   | Blueprint             | Spec silence                                                       | Default applied                                                                                                                                                     |
| --- | --------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | stroke-points         | The decoded number type                                            | `Float64Array`: decoding then re-encoding is exact, and geometry stays in doubles                                                                                   |
| D2  | stroke-points         | The decode cache's bound                                           | 500,000 points total, least recently used out first                                                                                                                 |
| D3  | stroke-points         | What a writer does with a coordinate outside its box               | Clamps float noise into `[0, 1]`; a non-finite value throws                                                                                                         |
| D4  | stroke-points         | How often an undecodable block is logged                           | Once per distinct block (a 64-entry set)                                                                                                                            |
| D5  | stroke-points         | Where the debug script lives                                       | `packages/document/scripts/expand-stroke-points.ts`, run by Node's type stripping with `scripts/ts-source-hooks.mjs`                                                |
| D6  | stroke-points         | Which base64 codec                                                 | The codec's own table codec: the document package cannot import api-schema's                                                                                        |
| D7  | document-storage      | Which outbox keys a room keeps                                     | Five kinds: `summary`, `tab` (per tab id), `cards`, `items`, `images`; the four document kinds share one D1 unit, each tab has its own, so a tab's push fails alone |
| D8  | document-storage      | How a drain groups its D1 writes                                   | One D1 batch per unit (the document's, then each tab's), at most 6 in flight; only succeeded units' keys go                                                         |
| D9  | document-storage      | Where the stats and the empty test are worked out                  | In the room, the D1-era SQL moved unchanged into the room's queries                                                                                                 |
| D10 | document-storage      | Which requests the worker hands to the room                        | Every path under `/api/documents/:id/`, as upstream; the collection (list, create), the realtime admission and the copy stay in the worker                          |
| D11 | document-storage      | The order of a create's two writes                                 | The room first, then the D1 row; a failed D1 insert purges the room                                                                                                 |
| D12 | document-storage      | How an unreachable room is purged later                            | A D1 tombstone, retried by the daily cron, 300 a run, at most hourly per room                                                                                       |
| D13 | document-storage      | Which write wins when two holders write in the same millisecond    | The larger SHA-256 of the body, so every holder picks the same                                                                                                      |
| D14 | document-storage      | What the row-cap constants are called once D1 no longer holds tabs | `SQLITE_ROW_MAX_BYTES`, `SQLITE_ROW_HEADROOM_BYTES`; `MAX_TAB_BYTES` unchanged                                                                                      |
| D15 | document-storage      | How a worker call to a content module is prevented                 | Content modules take `DocumentEnv`; the worker's `Env` has no `DOCUMENT_DB`, so it does not compile                                                                 |
| D16 | document-storage      | What a request answers when its room fails                         | 503 `room_unavailable`, logged with the path                                                                                                                        |
| D17 | document-storage-move | How the rooms become SQLite-backed under the same name             | Rename the key-value class aside (`LegacyDocumentRoom`), then a new SQLite `DocumentRoom`                                                                           |
| D18 | document-storage-move | When a document moves                                              | On its room's first request, and by a sweep every minute, whichever comes first                                                                                     |
| D19 | document-storage-move | Which rows the content hash covers                                 | The copied rows only; stats, image references, board statuses and holders are recomputed, not hashed                                                                |
| D20 | document-storage-move | The sweep's pace                                                   | 25 documents a minute, 6 at once, failures retried at most hourly                                                                                                   |
| D21 | document-storage-move | What a request answers while its move fails                        | 503 `content_moving` with `Retry-After: 5`                                                                                                                          |
| D22 | document-storage-move | The operator tool's form                                           | A Node script over `wrangler d1 execute --json`, refusing any statement but `SELECT`                                                                                |
| D23 | document-storage-move | How a room knows whose legacy room to ask                          | Every worker-to-room call carries `X-Document-Id`, set by the one stub helper in `room-client.ts`                                                                   |
