# Repositories blueprint defaults

One row per default applied where a spec is silent or qualitative.

| #    | Blueprint       | Spec silence                                                                                           | Default applied                                                                                                                                                                                                                                                                                                                                                                                                |
| ---- | --------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RL1  | repository-link | How `livedoc.toml` is parsed                                                                           | `smol-toml` 1.9.0 (the latest), bundled: the link file uses tables, arrays and arrays of tables, beyond the hand parser `config-file.ts` reads; its line and column name a syntax error                                                                                                                                                                                                                        |
| RL2  | repository-link | What this slice does with `[hooks]` and `[[sources]]`                                                  | Parse and validate, never refuse a known table: `[hooks]` admits only `block`, a boolean, refused by name otherwise; `[[sources]]` must be an array of tables and its tables' keys are left to diagram-sources; both are ignored by every command of this slice, with a debug line                                                                                                                             |
| RL3  | repository-link | The grammar of ids and `dir`                                                                           | Ids are the strings the api stores (the spec's `fld_…`, `doc_…` are illustrative): non-empty, no whitespace, at most 128 characters; `dir` normalised to POSIX segments, `.` allowed, `..`, absolute paths and a real path outside the link root refused (`invalid_dir`)                                                                                                                                       |
| RL4  | repository-link | Which directories `--all` and the mirror scan walk                                                     | Depth first in byte order of names; `.git`, `node_modules` and dot-directories skipped; symbolic links never followed; the mirror scan also skips any subdirectory holding its own `livedoc.toml`                                                                                                                                                                                                              |
| RL5  | repository-link | How the link's host is compared, and which profile the refusal names                                   | As origins with a leading `www.` ignored (as `parseDocumentUrl`); the refusal exits 2 and names the first `config.toml` profile with that host, else `--host <link host>`                                                                                                                                                                                                                                      |
| RL6  | repository-link | A covered folder the syncing account cannot find                                                       | Said once on stderr; that pass judges no mirror file outside coverage, so no file is removed for a folder the account cannot see                                                                                                                                                                                                                                                                               |
| RL7  | repository-link | What "folder path" is, for paths and for `INDEX.md`                                                    | Paths: the slugged names (`fileSlug`) of the folders below the covered folder down to the document's; empty for a listed document outside it. `INDEX.md`: the names from the space (`My Documents`, or the team's name), `/`-joined; `Shared With Me` when the folder is not visible                                                                                                                           |
| RL8  | repository-link | The link id's length, the state dir's discovery and modes                                              | First 16 hex of SHA-256 of the link file's real path; `git rev-parse --absolute-git-dir` from the link root (each worktree its own), else `<cacheDir>/links/<link id>/`; directories 0700, files 0600                                                                                                                                                                                                          |
| RL9  | repository-link | How `--relocate` moves a file git does not track                                                       | `git -C <root> mv` first; an untracked file, a missing `git` or a refusal falls back to a rename; empty directories left behind are removed                                                                                                                                                                                                                                                                    |
| RL10 | repository-link | What the offline overview shows as "edited" for a file with no `pulledAt`                              | The greatest `updatedAt` among the file's tabs, else 0                                                                                                                                                                                                                                                                                                                                                         |
| RL11 | repository-link | Two mirror files naming one document                                                                   | Both refused (`duplicate`), naming each other; neither is written or removed                                                                                                                                                                                                                                                                                                                                   |
| RL12 | repository-link | When an `in-step` document's outline file is rewritten                                                 | Only when it is missing, so CLIs of different versions never rewrite each other's outlines back and forth                                                                                                                                                                                                                                                                                                      |
| RL13 | repository-link | Whether `--dry-run` takes the lock or writes the local sync state                                      | Neither: it reads and prints, ending `dry run: nothing written`                                                                                                                                                                                                                                                                                                                                                |
| RL14 | repository-link | Which answers are transient, and whether a pass retries                                                | `429`, `5xx`, a timeout and a network failure are transient, kept and reported, not retried within the pass; `401` ends the pass before any write, exit 4                                                                                                                                                                                                                                                      |
| RL15 | repository-link | Whether a sync records read copies                                                                     | Yes, every tab it reads, as `pull` does (CLI24), so `tab diff --since` works from a synced revision                                                                                                                                                                                                                                                                                                            |
| RL16 | repository-link | When `INDEX.md` is rewritten, and what a document not read this pass shows                             | Rewritten only when its bytes differ; an `unreadable`, transient or refused document keeps its previous section verbatim (found by its `Link:` line), else is left out                                                                                                                                                                                                                                         |
| RL17 | repository-link | A pass's exit when documents fail differently                                                          | The highest exit among its actions (as CLI84); `unreadable`, `local-new`, `gone` and a lowered removal are 0, a refusal (`gone-changed` and `lowered-changed` included) 1, a transient 6 or 7; `--all` takes the highest across links. `link status` is not a pass: it exits 0 (spec, RL43)                                                                                                                    |
| RL18 | repository-link | How a waiting sync polls, and its exit when the wait ends                                              | Every 250 ms; exit 5 (`lock_held`, "conflict or held: retry"), naming the pid                                                                                                                                                                                                                                                                                                                                  |
| RL19 | repository-link | Whether `sync --watch` holds the lock between passes                                                   | No: per pass only, so `link status` and a one-off `sync` still run beside a watch                                                                                                                                                                                                                                                                                                                              |
| RL20 | repository-link | Which room events count as a document's "changes" for `--watch`                                        | Every event `classifyRoomOp` yields, comments included (the mirror holds an element's threads), settled by `WAIT_SETTLE_MS` per document                                                                                                                                                                                                                                                                       |
| RL21 | repository-link | How `--watch` learns that coverage changed                                                             | Coverage re-read every 60 s; entering documents get a stream and a pass, leaving ones a pass and no stream                                                                                                                                                                                                                                                                                                     |
| RL22 | repository-link | What `--watch` does after a room stream reconnects                                                     | A pass of that document, as after an op, instead of the `tab diff` notice `watch` prints                                                                                                                                                                                                                                                                                                                       |
| RL23 | repository-link | How `--watch` tells its own writes from a person's                                                     | Each path it wrote or removed is kept with the SHA-256 of what it wrote; an event whose file hashes to it is ignored                                                                                                                                                                                                                                                                                           |
| RL24 | repository-link | How `sync --watch` reports as `SyncWatch` when the verb is `sync`                                      | `Verb.telemetryType(input)`, read by `main.ts` before `pascalToken(verb.id)`; `CLI_COMMANDS` gains a `SyncWatch` row beside `Sync`                                                                                                                                                                                                                                                                             |
| RL25 | repository-link | The line `--watch` prints per sync                                                                     | `<HH:MM:SS>` in UTC, then the pass's action lines joined with `·`, or `in step`; a refusal or `unreadable` line again only after it changed                                                                                                                                                                                                                                                                    |
| RL26 | repository-link | How `link init --folder` names a folder                                                                | A full id, an id prefix of at least 4, or a name equal ignoring case, over personal and team folders; none or several exit 3 with the nearest or the candidates                                                                                                                                                                                                                                                |
| RL27 | repository-link | `link init --doc` given a share-link URL                                                               | Exit 2: a link file holds ids, and a share code is a credential of sorts                                                                                                                                                                                                                                                                                                                                       |
| RL28 | repository-link | Whether `link init` writes `host`                                                                      | Always, so a teammate on another profile is refused rather than syncing ids against the wrong host                                                                                                                                                                                                                                                                                                             |
| RL29 | repository-link | `sync --watch --dry-run`                                                                               | Exit 2: a dry run writes nothing, so there is nothing to watch                                                                                                                                                                                                                                                                                                                                                 |
| RL30 | repository-link | Whether the mirror file keeps the envelope's `exportedAt`                                              | No: it is a time, and the same revisions must write the same bytes; `parseDocumentEnvelope` reads its absence as 0                                                                                                                                                                                                                                                                                             |
| RL31 | repository-link | Which keys "keys sorted" sorts                                                                         | Every object's, at every depth, in `canonicalJson`'s order, so the whole file is one canonical form                                                                                                                                                                                                                                                                                                            |
| RL32 | repository-link | How names and outlines are made safe in Markdown                                                       | Names get a backslash before each backslash, backtick, asterisk, underscore, bracket, angle bracket, hash, pipe and tilde, and before a leading list marker; code spans and fences one backtick longer than the longest run inside                                                                                                                                                                             |
| RL33 | repository-link | How the `[sync]` and `[link]` fingerprints print beside `[cli]`                                        | `debugLog(io, scope)`; the sync modules log with scope `sync`, `link init` and its picker with `link`, under `LIVEDOC_DEBUG=1` only                                                                                                                                                                                                                                                                            |
| RL34 | repository-link | A lock whose holder died                                                                               | A holder on this hostname whose pid is not alive is stale: removed and taken over, logged; a holder on another hostname is never judged stale                                                                                                                                                                                                                                                                  |
| RL35 | repository-link | How the folder picker takes input, and what cancelling exits                                           | Line based on stderr: a numbered list, then `folder> ` read with the terminal's own line editing; a number chooses, other text narrows by path ignoring case, Enter alone, Ctrl-D or Ctrl-C cancels with exit 1; no raw mode, arrows or redraw, as the CLI draws no cursor movement (CLI blueprint "Accessibility"); choices are personal folders then each team's by team name, depth first, siblings by name |
| RL36 | repository-link | What a sync does at `none`, where states come from recorded revisions                                  | It reads coverage and revisions and records them in the local sync state, so `link status` has states; it writes nothing in the tree but the removal of lowered files; `sync --watch` ends after its first pass                                                                                                                                                                                                |
| RL37 | repository-link | Which "envelope fields" make a document `behind`, and how they are read                                | `document.name`, `document.presentation`, the tab order and each tab's `folder` (absent equal to none), compared at `files` against `GET /documents/:id`, read beside the overview; a hand edit of them is no local change and is written back                                                                                                                                                                 |
| RL38 | repository-link | How many folders the picker and its refusal show at once                                               | 20, as `LIST_DEFAULT_LIMIT`; the rest named in one line, reached by narrowing or by `--folder <name>`                                                                                                                                                                                                                                                                                                          |
| RL39 | repository-link | The refusal's shape when `link init` is not run in a terminal                                          | Exit 2 (`folder_needed`); one line per folder, `livedoc link init --folder <id>` with `--level` when given and a shell comment `# <path> (<library>)`, so each line runs as pasted; the first as the hint                                                                                                                                                                                                      |
| RL40 | repository-link | How `link init` knows the repository has a git remote                                                  | `git -C <cwd> remote` exiting 0 with any output; no git, a non-zero exit or no output prints nothing; no forge is asked, so the profile's host stays the only one contacted                                                                                                                                                                                                                                    |
| RL41 | repository-link | How the stable order compares                                                                          | Folder path by its slugged segments, segment by segment in UTF-16 code units, a prefix first; then the document name in code units; then the id; never `localeCompare`, so every machine orders alike                                                                                                                                                                                                          |
| RL42 | repository-link | Which generated Markdown a sync may remove                                                             | An outline file or `INDEX.md` only when its first line is still the generated line; one edited past that is left and named                                                                                                                                                                                                                                                                                     |
| RL43 | repository-link | What `link status` prints for a document it could not read                                             | `?` in the state column, the failure on stderr, exit 0 like every other row                                                                                                                                                                                                                                                                                                                                    |
| RL44 | repository-link | The local sync state's record shape                                                                    | Per document its name and per tab `{ rev, syncedAt }`, refreshed for every document whose state a pass decided and dropped when it is `gone`                                                                                                                                                                                                                                                                   |
| LC1  | local-copy      | What a `files` link inside a work tree with `binding = "branches"` does before Branch binding is built | Mirror files as the first slice; every page and file document held, reason `binding-unbuilt`, naming `[git] binding = "none"`; nothing of a git branch is ever written as main's                                                                                                                                                                                                                               |
| LC2  | local-copy      | How `[git] binding` gets into the link file                                                            | `link init --binding none\|branches`; without it inside a work tree, one stderr hint and no `[git]` table, so a git-bound link is never made by accident either way                                                                                                                                                                                                                                            |
| LC3  | local-copy      | A host whose overview carries no tab `kind` or `hash`                                                  | Read as a host without markdown and file tabs: native files held, reason `host-too-old`; mirror files as before                                                                                                                                                                                                                                                                                                |
| LC4  | local-copy      | The unit of the markdown spec's "character ranges"                                                     | UTF-16 code units of the base revision's text (JavaScript string indices), the same in `editsBetween` and the api's `patch`                                                                                                                                                                                                                                                                                    |
| LC5  | local-copy      | Editor leftovers that are not dotfiles                                                                 | `*~`, `#*#` and `.#*` are ignored as `editor-leftover`, so an Emacs or Vim backup never becomes a document                                                                                                                                                                                                                                                                                                     |
| LC6  | local-copy      | "Files git ignores" when git takes no part                                                             | Inside a work tree (a `binding = "none"` wiki): `git check-ignore --stdin`, one call per pass. Outside one: no `.gitignore` is read; `[mirror] ignore` is the copy's own list                                                                                                                                                                                                                                  |
| LC7  | local-copy      | How `[mirror] ignore` globs match                                                                      | `picomatch` 4.0.7 against the path relative to `dir`, POSIX separators, `dot: true`; a glob ending `/**` also matches the directory itself                                                                                                                                                                                                                                                                     |
| LC8  | local-copy      | How a large first sync stays under the api's per-token limits                                          | A `Pacer` of `SYNC_WRITES_PER_MINUTE` (120, under `WRITE_RATE_LIMITER` 300/60 s) and `SYNC_READS_PER_MINUTE` (100, under `API_TOKEN_READ_RATE_LIMITER` 120/60 s), waiting rather than failing; `[sync] paced` logs each wait                                                                                                                                                                                   |
| LC9  | local-copy      | Whether every pass reads every covered document's overview                                             | A native document whose list entry (`savedAt`, `name`, `folderId`) equals the recorded one and whose file matches its record is `in-step` with no read; mirror-file documents are read as before (their comments do not move `savedAt`)                                                                                                                                                                        |
| LC10 | local-copy      | Which files a narrowed `--watch` pass judges moves over                                                | The whole scan, always: a lone half of a rename never deletes a document                                                                                                                                                                                                                                                                                                                                       |
| LC11 | local-copy      | How "as git judges a rename" is measured                                                               | Bytes of lines common to both texts, counted as a multiset, over the larger text's bytes, as git's diffcore counts text by line                                                                                                                                                                                                                                                                                |
| LC12 | local-copy      | A directory renamed in the folder                                                                      | When every document recorded under one directory moved to one new directory and no folder of that name exists, the folder is renamed, keeping its id (and a wiki mark on it)                                                                                                                                                                                                                                   |
| LC13 | local-copy      | When "a folder whose documents have all gone goes with them" deletes a LiveDoc folder                  | Only a folder this pass emptied, holding no document and no subfolder; never the covered folder                                                                                                                                                                                                                                                                                                                |
| LC14 | local-copy      | Temporary files and modes of the files a local copy writes                                             | `.<name>.<pid>.tmp` beside the target (a dotfile, so `rg`, watchers and other syncs skip it), then `rename(2)`; a rewrite keeps the target's mode; a new file 0644, or 0755 when executable, narrowed by the umask                                                                                                                                                                                             |
| LC15 | local-copy      | How a watch of hundreds of documents opens its room streams                                            | In index order, `SYNC_STREAM_OPENS` (10) at a time                                                                                                                                                                                                                                                                                                                                                             |
| LC16 | local-copy      | Where a file name splits into name and extension                                                       | At the last dot; no dot: extension `''`; `archive.tar.gz` is `archive.tar` and `gz`                                                                                                                                                                                                                                                                                                                            |
| LC17 | local-copy      | The adopted document's id, and how adoption stays exactly-once                                         | A random id chosen by the CLI and journalled in `adoptions.json` before the create; a resumed pass asks the api for it before creating again                                                                                                                                                                                                                                                                   |
| LC18 | local-copy      | How "one watch per copy folder" is enforced, and its exit                                              | An exclusive `watch` file in the state directory; a live holder exits 5 (`watch_running`) naming the pid; a dead holder on this hostname is taken over, as RL34                                                                                                                                                                                                                                                |
| LC19 | local-copy      | Where set-aside bytes are kept, and for how long                                                       | `<state dir>/set-aside/<startedAt>-<file name>`, 0600, never pruned: they are the person's bytes                                                                                                                                                                                                                                                                                                               |
